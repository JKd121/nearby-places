本 Spike 只研究 POI 图片、外部位置/导航链接和现有结果字段。没有修改生产 UI、resolver、附近搜索语义、分页、排序或过滤，也没有调用第二 Provider。

隔离脚本：`scripts/spikes/result-card-enrichment-spike.ts`

## A. POI photos

### Provider 文档证据

高德 POI 2.0 文档将 `photos` 列为可通过 `show_fields` 请求的可选字段，图片项包含 `title` 和 `url`。同一文档说明 `show_fields` 可以请求多个字段类，因此隔离脚本请求 `show_fields=business,navi,photos`。官方文档没有为本项目的 8 个类别或香港地区提供稳定照片覆盖率保证，也没有在本轮获得真实返回样本。

来源：

- https://lbs.amap.com/api/webservice/guide/api-advanced/newpoisearch
- https://lbs.amap.com/api/webservice/guide/api/newpoisearch

### 两个地点、8 类真实样本

| 地点 | 类别 | 返回数 | 有照片 | 首张 URL 协议 | 直接前端可用性 | 状态 |
|---|---|---:|---:|---|---|---|
| 深圳北站 | hotel / mall / hotpot / bakery / dessert / ktv / billiards / gym | NOT_RUN | NOT_RUN | NOT_RUN | NOT_RUN | 缺少 Key |
| 香港城市大学结构化输入 | hotel / mall / hotpot / bakery / dessert / ktv / billiards / gym | NOT_RUN | NOT_RUN | NOT_RUN | NOT_RUN | 缺少 Key |

脚本在 Key 注入后会对两个地点依次执行 8 类 types-only Around 请求，逐 POI 只输出名称、type、typecode、照片数量、协议和可用性布尔值，不输出完整响应或 URL。请求间保持约 500ms；不存储 secret-bearing URL。

### 图片决策

当前不能证明所有类别有足够稳定的照片覆盖，也不能证明照片内容相关性或授权要求。因此生产卡片暂不应依赖图片字段。

若后续真实样本显示覆盖稳定，建议采用：

1. 有真实可用图片时显示原图；
2. 没有图片、非 HTTPS 或 URL 无法安全加载时使用本地类别 fallback；
3. fallback 不伪造 AMap 图片，也不把图片缺失视为错误。

当前答案：`NOT_READY`，等待真实样本。

## B. 查看位置 / 去这里

现有 `Place` 已包含 `longitude` 和 `latitude`，因此不需要新增 Provider 或地图 SDK 即可生成外部链接。

最小安全方案是由服务端或浏览器使用 `encodeURIComponent` 编码名称，生成不含 Web Service Key 的 HTTPS URI，例如：

- 查看位置：`https://uri.amap.com/marker?position={longitude},{latitude}&name={encodedName}&callnative=0`
- 去这里：`https://uri.amap.com/navigation?to={longitude},{latitude},{encodedName}&callnative=0`

高德 URI 文档说明 marker URI 适用于按经纬度标注单点，navigation URI 支持移动端和 PC 端。`callnative=0` 让链接优先使用 Web fallback；移动端后续可在明确验证后选择 `callnative=1`，但第三方内置浏览器可能无法调起 App。当前不实现按钮或链接。

来源：

- https://lbs.amap.com/api/uri-api/summary
- https://lbs.amap.com/api/uri-api/guide/mobile-web/point
- https://lbs.amap.com/api/uri-api/guide/travel/route

结论：坐标足以支持一个安全的“查看位置 / 去这里”动作；生产实现仍需对名称进行 URL 编码、对坐标做有限数值校验，并设置 `rel="noreferrer"`（如使用新窗口）。不需要新 Provider 或数据库。

## C. 当前 Place 元数据审计

| 字段 | 当前来源 / 状态 | 丰富卡片结论 |
|---|---|---|
| name | AMap POI 基础字段，当前已标准化 | 可用作主标题 |
| category | 本地 8 类配置映射 | 可用作类别标签，不代表上游绝对正确 |
| distance | `distanceMeters`，优先 AMap native，始终计算 Haversine fallback | 可用；必须继续标明来源语义，不伪装为纯 API 字段 |
| rating | `business.rating`，缺失为 null | 可选显示；缺失保持 null |
| cost | `business.cost`，缺失为 null，按类别口径使用 | 只能按既有类别规则弱化显示，不能当作精确报价 |
| tag | `business.tag`，缺失为 null | 美食类可选显示，缺失正常 |
| address | AMap 基础字段，缺失时为空字符串 | 可用作辅助信息，缺失需安全文案 |
| coordinates | AMap `location` 解析后的经纬度 | 足以生成 marker / navigation URI |

以下字段没有当前 Provider 证据，必须保持不存在，不得从 UI 或文案推断：

- review count
- hotel nightly price
- realtime opening status
- favorites state
- 图片内容相关性或用户生成内容授权状态

## D. 最小新增契约建议

如果真实照片 Spike 通过，最小增量可以是：

```ts
type PlacePhoto = { title: string | null; url: string };
photos: PlacePhoto[];
```

但在真实覆盖率、URL 稳定性、内容相关性和授权要求验证前，不应把 `photos` 加入生产 `Place` contract。位置链接可以从现有坐标派生，不要求新增 `Place` 字段。

## E. 是否需要新 Provider 或数据库

- 新 Provider：不需要。
- 数据库：不需要。
- 地图 SDK：不需要。
- 图片缓存或代理：本 Spike 没有证据支持，暂不引入。
