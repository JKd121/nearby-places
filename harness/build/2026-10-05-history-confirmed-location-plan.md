# 历史记录直接搜索：实施方案

日期：2026-10-05。阶段：COMPLETE（本地实现、自审及可执行验证）；用户回复“我确认授权”，批准完整本地实施、自审和验证范围。在线数据库迁移及发布仍不在本轮授权内，真实 PostgreSQL 持久化集成未验证。最终结果见 `2026-10-05-history-confirmed-location-verification.md`。

## 目标、来源和边界

- CONFIRMED：用户明确点击历史应直接进入周边搜索和结果，不重复确认候选地点。
- CONFIRMED：用户进一步要求保存能够恢复周边搜索能力的全部已确认地址信息；每条可点击历史必须可直接搜索，不接受“需补确认”或点击后要求重新搜索作为历史恢复行为。
- CONFIRMED：保存上次已确认的地点，以确定的经纬度作为搜索中心；名称、地点类别、地址及可用的高德 POI ID 可以帮助识别。
- CONFIRMED：周边结果每次实时重新查询；不保存或恢复旧结果、筛选、排序或翻页状态。
- 沿用原历史中的服务类别和半径。结果默认进入现有“全部”分类视图，保留现有展示和分页规则；本轮不扩展为高德全量数据抓取。
- CONFIRMED：没有已确认地点信息的旧记录保留在数据库，历史列表只显示可直接搜索的完整记录。授权来源：用户回复“接受：保留旧数据，仅显示可直接搜索的完整记录”。原“需补确认/要求重新搜索”建议已被用户否定，不再实施。不能从原文本推断当时选中的地点，不能默选第一个候选。
- OUT_OF_SCOPE：历史结果快照、全量分页、新产品页面、依赖升级、历史加载/删除性能追加修复、照片/交通扩展、Git 发布与生产部署。

本轮分支：现有历史回放行为修正。先核对相关本地路径与保存数据，再针对高德中心点契约核对官方文档；不建立新的历史恢复服务或引入通用框架。

## 已检查证据和复用选择

- `SearchApp.tsx` 的 handleHistorySelect 清空已确认地点与结果，调用 resolveLocationForQuery；needs_confirmation 分支返回并等待 confirmCandidate，然后才自动调用 searchNearbyForSnapshot。
- SearchHistory schema、history POST/GET、前端 SearchHistoryItem 只有 query/categoryIds/radiusMeters/searchedAt 等字段；没有已确认中心。
- 现有 `/api/search` 经 parseConfirmedSearchRequest 校验中心与 resolvedLocation 坐标一致，executeResolvedSearch 直接搜索各类别，不调用 geocode。可直接复用。
- 现有 LocationCandidate 已包含 id/name/placeType/city/district/address/location，地址解析结果允许 id=null。可复用为保存契约，不强制为所有地点补 POI ID。
- 现有去重只含输入/类别/半径，不包含中心；相同输入选中不同地点会被合并。
- 2026-10-04 已批准历史体验计划明确保留原回放含义和数据模型，不能把旧阶段的实施/发布授权视为本轮授权。
- 已核对安装的 Next.js Route Handlers 指南：继续使用现有 app route 与 POST，不新增页面路由。
- 高德官方搜索 POI 2.0 文档（2026-10-05 检查）：周边接口 `/v5/place/around` 接收 location 中心点及 radius；location 顺序为经度、纬度。POI ID 可用于 ID 搜索，但直接周边搜索不需要额外做 ID 查询。
  来源：https://lbs.amap.com/api/webservice/guide/api-advanced/newpoisearch

推荐最小改动：扩展现有历史记录保存确定中心，点击历史复用现有已确认地点搜索链路。名称/类型作为展示信息，不用拼接更长的文本重新解析。不安装依赖或复制外部代码。

## 已批准实施范围

1. 为 SearchHistory 增加 confirmedLocation JSON 字段，保存规范化后的完整 LocationCandidate，包括名称、经纬度、地址、城市、区县、地点类型与可用 POI ID。为兼容现有行迁移可暂时允许数据库字段为空，但新版本写入必须带完整地点对象；有效名称与有限且合法的经纬度为必要条件，其他字段按现有 nullable 类型保留，不能为了形式完整而伪造地址或 ID。
2. 更新 history contracts/service/repository/route 及前端历史 store，保存并返回已确认地点。匿名访客归属与公开字段过滤继续执行；校验实际业务类别和半径。写入缺失/非法地点信息时拒绝保存，不生成只能恢复原输入的不完整历史。读取及点击同样校验完整性，不能以重新解析文本或重新选择候选作为降级流程。读取最近10/20条应按完整记录计算，不让更近的不完整旧行挤掉有效记录；列表补位和删除也只针对可见有效记录。旧数据库行不删除或改写。
3. 去重继续包含规范化输入、服务类别和半径，增加确定中心的经纬度，避免不同中心被合并；同一中心重复搜索更新确认信息及时间。POI ID 为可空元数据，不作为周边查询的必要前置条件。
4. 首次周边搜索有成功类别时，沿用现有 best-effort 保存时机，同时保存用户确认的地点。仅确认地点但未搜索，不新增历史。
5. 点击完整历史恢复确定中心、输入、原类别和半径，直接调用 searchNearbyForSnapshot，不请求 `/api/resolve-location`；等待最新结果后进入现有结果视图。连续点击、改输入或条件时继续用 requestId 防止旧响应覆盖新状态。
   历史列表沿用现有样式，标题显示已确认名称并显示已有地址，方便区分同一输入选择的不同中心；原始输入仍保存并在恢复时回填。该局部调整在浏览器发现两个记录原标题相同后实施，需对更新版本重新验证。
6. 提供新增可空字段的兼容迁移文件，保留旧数据库行；历史列表过滤没有有效中心的旧行。首次有效搜索按新去重键保存完整记录，不覆盖旧行伪造当时选择。新旧浏览器并存时，旧请求不能再生成不完整记录；保存失败仍不阻塞其已经取得的搜索结果。

本轮交付边界：本地可审阅实现、数据库迁移文件、自审、现有 gates 和实际浏览器验证。批准本方案不自动授权在线数据库迁移、远程提交或部署；完成本地可执行检查后交付具体迁移及发布内容。若没有可用的隔离数据库，仅将真实 PostgreSQL 集成标为未验证，不用受控浏览器响应宣称数据库已生效；不宣称线上修复完成。
