在现有结果列表基础上，提升卡片的信息层级与扫描效率，并增加一个不携带密钥的 AMap “查看位置”外链。只使用当前 `Place` 已有字段，不改变搜索、排序、过滤、分页、dedupe 或状态语义。

## 结果卡片结构

每条结果保持 list-first、compact：

```text
编号   名称                              距离
       类别 · rating · cost              查看位置
       tag（存在时）
       provider address（存在时）
```

视觉优先级：名称 > 距离 > 类别/rating/cost > tag > address > 查看位置。距离继续使用现有 `formatDistance`，不暗示步行时间、驾车距离或预计到达时间。

## 字段显示规则

- `name`：主标题，直接使用 provider 值。
- `category`：使用现有本地类别 label。
- `distanceMeters`：使用现有 formatter。
- `rating`：继续使用现有 null-safe formatter；缺失不显示 `null` / `undefined`。
- `cost`：继续使用现有类别策略；酒店、商场、台球厅不新增消费字段；健身房保持弱化参考语义。
- `tag`：只显示 provider 返回并经现有 `truncateTag` 处理的内容，不生成新标签。
- `address`：只显示 provider 地址，移动端允许截断。
- 坐标：仅用于构造 marker URI，不直接新增坐标文案。

禁止新增 review count、hotel nightly price、realtime open/closed、favorites 或照片字段。

## URI 与安全设计

生成示例（示意，不在代码中硬编码完整用户数据）：

```text
https://uri.amap.com/marker?position=lon%2Clat&name=encodedName&src=nearby-places&coordinate=gaode&callnative=0
```

- `URLSearchParams` 负责编码名称和参数。
- `callnative=0` 默认走 Web fallback，避免假设桌面或移动端一定安装 AMap App。
- 外链使用新标签页和 `noopener noreferrer`。
- 不使用客户端 AMap Web Service 请求，不暴露 Key、provider request URL、info 或 infocode。
- 本阶段只提供“查看位置”，不加入“去这里”第二动作，避免卡片变拥挤，也不假设桌面端起点位置。

官方依据：

- https://lbs.amap.com/api/uri-api/summary
- https://lbs.amap.com/api/uri-api/guide/mobile-web/point

## 移动端行为

- 375px、390px、430px 均不得横向溢出。
- 长名称最多按现有标题规则换行。
- 距离保持右侧可读；查看位置为至少 32px 高的可点击区域。
- tag 和 address 继续弱化并允许截断。
- 没有有效坐标时不渲染 action，不显示错误占位。

## 无障碍

- 使用语义 `<a>`，不使用 div/span click handler。
- `aria-label` 包含 POI 名称，例如“在高德地图中查看深圳北站”。
- 保留可见 `:focus-visible` 样式，颜色对比度满足现有主题。
- 新标签页行为由可见文案和 aria label 传达，不改变键盘顺序。
