# 历史记录体验优化：设计与实施计划

日期：2026-10-04。当前阶段：`COMPLETE`（本地交付）。用户已明确批准“批准现在的方案”。以下原始建议随具体方案批准，成为本轮实施与验收约定。最终结果及实际证据见[验收记录](2026-10-04-history-experience-verification.md)。

## 目标、授权与边界

目标：让查看历史记录、删除记录和补位无需阻塞已有列表，缩短首次点击后的等待。

任务分支：已有功能的性能与交互修复。先前只读调查已定位连接成本和 DELETE → GET 串行等待；本阶段根据这些证据设计方案。

授权来源：用户先确认“进入到设计和plan阶段，我确认”，随后明确“批准现在的方案”，授权所示方案的实施、自审和验证。部署不在授权范围内。

| ID | 要求 | 状态与来源 |
| --- | --- | --- |
| H1 | 同时改善首次打开、再次打开和删除后更新 | CONFIRMED：用户确认第一点 |
| H2 | 有可用记录时，打开立即显示 | CONFIRMED：用户确认第二点代表修改后的效果 |
| H3 | 点击删除后，该项立即消失 | CONFIRMED：同上 |
| H4 | 首次没有可用缓存时，允许短暂加载提示 | CONFIRMED：同上 |
| H5 | 页面内存缓存、预读时机、20 条备用数据、失败恢复方式、30 秒新鲜期、8 秒超时及 100 ms 指标 | CONFIRMED：用户批准完整具体方案，原始建议成为本轮约定 |

建议实施范围：历史记录前端读取/显示/删除/保存后的缓存同步，以及为备用记录支持有界读取的现有 GET 接口。沿用 PostgreSQL、匿名访客 Cookie、数据模型、搜索重放、排序及去重语义。

本阶段不包含：新产品界面或视觉重做、账号、收藏、全量历史分页、跨设备同步、浏览器持久化缓存、数据库迁移、连接池参数调整、部署区域修改、定时保活、第三方缓存服务、提交发布或部署。历史记录数据库与匿名识别继续作为事实来源。

## 已有证据与性能边界

完整基线见 [只读排查记录](2026-10-04-history-performance-investigation.md)。实际 Prisma 首次读取 2037 ms，随后约 267 ms；数据库内部 SQL 执行约 0.4 ms。线上只读 GET 总耗时为 1807 / 558 / 261 / 246 ms。连接空闲回收后读取得到 1945 ms，随即读取 276 ms。

上述基线没有实际浏览器 click-to-paint 数据，也没有生产 DELETE 数据；不能用它代替浏览器体验验证。一次本机首次查询曾耗时 36.6 秒，网络/连接波动需通过明确的等待结束和错误状态处理。

本方案将等待移到后台、提前读取并复用已有数据；不会把远程数据库的新连接时间变成零。首次点击发生在预读完成之前时，仍需等待真实响应。首开真实数据时间必须重新测量，不能只凭加载提示更快就宣称数据查询变快。

## 用户可见行为

| 场景 | 设计后的表现 |
| --- | --- |
| 页面刚可交互 | 后台预读一次历史，主页面和地点输入正常使用；预读失败不在关闭的面板外打断用户 |
| 首次访问、尚无访客 Cookie | 服务端建立匿名 Cookie 并返回空列表；新身份不存在已有历史，无需为确认空列表查询数据库 |
| 预读完成后第一次打开 | 已有记录直接显示，成功读取过的空列表直接显示“暂无搜索历史” |
| 马上点击、预读仍在进行 | 显示“正在读取最近搜索…”，复用同一读取请求，不另发一份 |
| 再次打开，有缓存 | 立即显示；超过建议的 30 秒新鲜期或已标记需要更新时后台校验，已有列表保持可用 |
| 删除一项、有备用记录 | 立即移除目标项，下一个备用记录同时顶上；列表继续显示、可操作 |
| 删除一项、无备用记录 | 立即呈现剩余记录，后台尝试补位；只有确认无记录且没有待处理操作时显示空状态 |
| 连续删除多项 | 每次点击立即生效；按 ID 跟踪待处理操作，不锁住整个列表；同一 ID 防重复提交 |
| 删除明确失败 | 恢复该项并提示“删除失败，已恢复这条记录，请重试”；保留其他已成功操作 |
| DELETE 超时、网络中断或 404 | 先校验当前服务端列表来判断结果；校验也失败时恢复该项并提示“暂时无法确认删除结果，已恢复显示，请重试”，不宣称服务端已恢复或删除成功 |
| 后台刷新失败 | 保留已有记录，在面板内轻量提示“暂时无法更新，已显示上次记录”及重试入口 |
| 无缓存读取失败/超时 | 显示“读取历史记录失败，请重试”；不把读取错误当成没有历史 |
| 新搜索保存成功 | 使用 POST 返回的真实 ID、规范化字段和时间更新本地列表，按现有去重语义移动到最前；不为显示新记录再等待 GET |
| 新搜索保存失败 | 保留现有 best-effort 行为，不阻塞搜索结果，不添加伪造的“已保存”记录 |

建议缓存仅存在于当前页面实例内：刷新、关闭或另开页面后重新预读。这样沿用匿名身份机制，无需公开 visitorId 或新增持久化数据留存。它覆盖本轮确认的“已有可用缓存即显示”；跨刷新立即显示不在这个建议范围内。

## 有限的数据与请求策略

1. 页面可交互后，通过一次可清理的普通延迟任务发起后台预读；建议延迟 200 ms。早于此时的点击直接启动读取并取消计划任务。React Strict Mode 的额外 effect 检查不能造成重复的有效预读请求。
2. 最多缓存 20 条，仍显示最近 10 条。备用记录让删除后的补位在本地完成；备用耗尽时也不为等补位隐藏列表。
3. 只保留一个有效 GET；预读、打开、重试和补位复用它。成功读取为空也是缓存有效状态，不能因数组长度为 0 反复请求。
4. 同一页面的历史 GET/POST/DELETE 使用有限的顺序协调，避免没有访客 Cookie 时，并发请求分别建立两个身份。UI 响应与网络排队分开；删除在入队时就局部更新。
5. 待删除 ID 从所有新响应中暂时过滤。读取版本与修改时序受控，旧 GET 不能让已删除项重现或覆盖新保存的项。成功删除后在本地确认移除；明确失败只恢复这一项，不恢复整个旧列表。
6. 连续操作完成后合并安排一次后台补位/校验，避免每项删除强制刷新整个面板。必要校验仍发 GET，但不延长用户可见删除响应、不卸载列表或冻结其他项。
7. 每个实际发出的历史请求建议设 8 秒前端超时；超时结束该请求的等待并允许后续操作继续。前端中止不等于数据库已停止执行，写操作按结果不确定的流程处理；不盲目自动重试写操作。
8. 后台刷新保持列表节点和条目 ID key；关闭面板可以让合法预读完成用于下次打开。页面销毁时清理定时任务、取消读取并阻止过期响应更新状态；已经发出的写操作不假装可撤销。

## 接口及受影响文件

- `src/web/SearchApp.tsx`：历史面板接入独立的页面状态逻辑；打开、删除、错误和保存后的同步；搜索重放继续使用当前路径。
- 建议增加 `src/web/useSearchHistory.ts`，以及实现确有需要的有限状态/请求模块，保持每个页面实例独立；不做跨产品的缓存框架。最终文件拆分以能验证真实异步行为的最小实现为准。
- `app/api/history/route.ts`：GET 支持可选的 `limit=20`，省略参数继续返回默认 10 条。仅允许 10 或 20，非法值返回 400。沿用 cookies 获取访客；GET 发现没有 Cookie 时，创建新匿名身份并直接返回空列表，避免查询这个尚未保存过记录的新身份。已有 Cookie 正常访问数据库，POST/DELETE 继续遵守现有归属校验。响应字段保持当前公开字段，建议明确 `Cache-Control: private, no-store`，避免共享 HTTP 缓存参与匿名列表读取。客户端内存缓存由本页面管理。
- `src/history/service.ts` / `repository.ts`：复用已存在的有界 limit 参数与查询；默认 10、最大 20。预计无需修改 schema 或索引；只有必要的类型/契约衔接才触及这两处。
- `app/globals.css`：仅可能新增状态文字、重试入口所需的局部样式，复用现有色彩、字号、按钮与间距。
- 相关历史状态及 route 测试：覆盖本轮异步业务风险，纳入已有 npm test 流程。不升级依赖或增加端到端测试基础设施。

## 视觉与操作契约

目标用户任务：快速找到近期搜索并再次执行，或移除不需要的记录。

- KEEP：历史入口位置、输入框下方的面板、最近 10 条密度、条目主标题/类别数/半径/时间、当前字体与色彩、原生按钮和 aria-expanded、最近搜索 region。
- ADAPT：借用开源模式的本地即时更新、状态与数据分离、失败恢复；后台更新提示放在面板内，不盖住可用内容。
- REPLACE：全列表 loading 替换已有记录、删除成功后等待 GET 才显示、全局删除禁用。
- DO NOT COPY：Algolia 品牌与自动补全界面、SWR 示例应用界面、第三方素材；不改变历史回放的业务含义。
- 鼠标/触控删除不导致整个面板意外关闭；键盘删除后将焦点移到相邻可操作项，无剩余项时返回历史入口。失败恢复不抢走用户当前焦点。
- 普通后台更新不重新挂载列表，滚动位置保持；列表缩短到滚动范围不足时允许浏览器正常夹取 scrollTop。
- 沿用现有断点，在 390 px 移动端和 1280 px 桌面端检查长地点名、错误文案、滚动和删除按钮。错误通过 role=alert 或适当的 live region 宣告，普通更新避免重复播报。
- 不增加阻塞输入的过渡动画；沿用现有视觉意图，必要时仅调整历史面板动效，使内容首次可读绘制满足即时响应目标，尊重已有减少动态效果规则。无需图片、音频或新资产。

## 实施顺序、审查及交付边界

1. 在批准的当前 checkout 中实现针对历史的缓存和异步状态，以及有界 GET 接口；保持既有访客和响应契约。
2. 接入预读、打开、删除、保存响应与错误提示，完成局部补位及焦点/滚动处理。
3. 自审需求符合度及接口、并发和错误语义。没有独立审查人员时如实注明同一 Agent 自审。
4. 对上述受影响异步路径执行测试，运行项目 gates，再取得实际浏览器行为与性能对比证据。
