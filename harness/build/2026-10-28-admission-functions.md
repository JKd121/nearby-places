# 准入短事务与两批次链路：独立 PR 交付

基于 master 5e94d44b763203d54f0873343bed12b7c9517653（已包含预热 PR #28），分支 Nearby-准入短事务与两批次链路。本 PR 覆盖数据库函数、流水执行器、运行时衔接、测试、CI 和对应说明。

## 问题与改动

原准入每阶段五条 SQL 及 BEGIN/COMMIT，经 Prisma 交互式事务逐条往返；真实只读诊断中三条操作累计约 896ms，下一条时钟查询触发 800ms 交互事务过期的 P2028。

新增 amap_admission_reserve_v1、amap_admission_grant_v1 两个 SECURITY INVOKER 函数。各自在数据库内部按资源、绑定顺序加锁、读取时钟并执行校验；放行时原子提交上海日/月额度、消费水位及速率状态。迁移仅创建函数，保留既有表、触发器和政策数据。

专用 pg 池启用已有依赖的 pipeline，每阶段独占连接，同步入队 BEGIN、事务内限时配置、参数化函数 SELECT、COMMIT，统一等待所有结果及明确 COMMIT 确认。正常路径两个批次；就绪等待继续在应用侧执行并释放连接，必要时最多增加一次 grant 检查。API、一次性许可、公开错误及部分结果行为沿用。普通历史 Prisma 配置保留。

保留短准入 2 秒、连接获取 600ms、SQL 800ms、锁 150ms、驱动读取 1200ms，以及资源额度、800ms 放行间隔、800ms 宽限和 400ms 许可时限。取消后排空批次；迟到连接统一归还，未结算的连接申请设每执行器 12 个上限；SQL 回滚的健康连接复用，缺少提交确认、部分派发或连接错误时销毁连接。提交不确定时停止发送，沿用保守消耗、无重试/退款的行为。

固定失败日志包含阶段、连接获取/批次/总耗时、剩余预算、SQLSTATE、公开错误码及已确认提交状态；日志省略原始异常、SQL、参数、凭据和资源标识。成功路径静默。执行期间 pg error 事件有显式监听和清理。

## 发布顺序与兼容

目标环境先应用新增函数迁移（Prisma CLI 显式 --config prisma7.config.ts），再发布应用；Preview 先用模拟高德验收启动/恢复、完整准入、取消及额度计数，再安排真实调用。缺少函数时返回既有 ADMISSION_UNAVAILABLE。应用回滚保留函数和账本。

原工作区实验 CLI 的运行时 close 适配随实验分支后续交付，本 PR 基于现有 master 独立运行。原有其他成果通过入场哈希核对保留。

本次交付使用临时 loopback PostgreSQL 和模拟高德；现有开发/生产数据库及真实高德调用均为零。用户授权为提交、推送并创建 PR，交付在 PR 阶段停止。
