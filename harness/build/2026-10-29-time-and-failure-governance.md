# 时间治理 Stage A 与失败调度 Stage B

日期：2026-10-29，Asia/Shanghai。基于当前工作区完成本地实现与验证。入场分支 `Nearby-多类别真实数据探索-V1`、HEAD `7a629de`；既有预热、短事务、诊断和 POI 实验改动保留。本轮交付包含工作区源码和一条新迁移，提交及远端交付留待后续授权。

## 只读影响面核验

- `request-context.ts` 已有单调时钟、信号和可取消等待；原子上下文只接收父信号，准入另外维护 `end`、局部剩余时间及超时重映射。
- `search/service.ts` 每个非末尾类别再等待 500ms；数据库准入独立维护资源速率。十类别包含九次额外计划等待，合计 4500ms。
- `classify.ts` 原来把准入等待、数据库、额度及认证共同映射为 `stop`；调度器直接跳过全部后续类别。
- Route 的生命周期与搜索各有取消包装。总期限触发时，外层可先于搜索的错误处理返回 504，需要可同步取得的完成快照才能可靠保留结果。
- 预热拥有实例级共享探测；SQL、锁及驱动限时保护后台工作，取消后的批次继续排空并归还连接。这些清理责任沿用。

## Stage A：时间与等待责任

| 操作／等待 | 保留理由与责任 | 预算关系与计算 |
| --- | --- | --- |
| 请求正文读取、解析及搜索 | 生命周期负责整条请求 | 默认总期限 60s；使用 `performance.now()`，正文读取前开始 |
| 实例级共享准备 | 数据库准备协调器共享连接探测，避免重复启动 | 独立 10s 探测上下文；调用者受自身总期限／取消约束；单个等待者取消后共享探测继续 |
| 准入总时限 | 准入服务控制资源预约至许可消费 | 子上下文取 `min(2000ms, 父剩余时间)`；本层结束为 `ADMISSION_WAIT_EXCEEDED`，父期限结束保留 `REQUEST_DEADLINE_EXCEEDED` |
| 借用连接 | 数据库执行器限制池队列等待 | `min(600ms, 当前准入／预约剩余)`；复用上下文；超时后的迟到连接归还 |
| SQL／锁／空闲事务 | 数据库内约束语句与锁等待，并保护中断事务 | SQL、空闲事务最多 800ms，锁最多 150ms，均受派发时剩余时间缩短；这些保护覆盖不同运行状态 |
| 驱动读取 | 驱动为已派发查询提供最终收尾上限 | 最多 1200ms，并按派发时剩余时间缩短；取消后排空全部已派发结果 |
| 预约到时隙 | 准入负责资源调度，请求上下文负责等待与取消 | 数据库在资源锁内取 `max(now, nextReservationAt, nextGrantAt)`；接收预约结果后等待 `delayMs`，期间释放连接 |
| 最终放行返回 WAIT | 并发请求可在预约后推进实际放行屏障 | 接收后等待返回时长，最多复查一次；受总准入及预约有效期约束 |
| 预约及一次性许可有效期 | 阻止过期、重放及提交不确定后的发送 | 预约从 reserve 调用起点加数据库返回有效时长；许可从 grant 调用起点加有效时长，并受预约和总准入约束；最终 `assertValid` 同步检查 |
| 单次高德 HTTP、响应读取 | 传输层保护独立调用 | 准入后建立子上下文，取 `min(8000ms, 父剩余时间)` |
| 产品类别之间 | 调度器直接进入下一类 | 固定 500ms 等待已删除；仍按原顺序串行 |
| smoke CLI、POI 实验间隔 | 独立调研入口自行声明节流策略 | smoke 的原有间隔移到 CLI 编排层；POI 实验保持原状 |

2s 继续作为单次准入上限，避免一类长期占据请求；整体预算充足时，后续类别仍可获得自己的准入机会。资源自身的 wait、grace、interval、permit TTL 和额度保持原值。物理建连上限仍为 8s；请求或借用等待先结束后，底层建连按原有机制收尾。新鲜期 10s 和失败冷却 1s 仍由共享准备协调器记录，它们决定连接状态复用。

时间接口新增父上下文支持、`check()` 和 `wait()`。`check()` 在计时器尚未被事件循环派发时也检查单调截止，保留首先触发的 typed reason；`remainingMs()` 直接复用同一预算。底层数据库和网络保护继续通过原生超时参数落实。

### 删除固定等待后暴露的预约错位

原预约仅参照 `nextReservationAt`，实际放行还参照 `nextGrantAt`。固定 500ms 曾使下一类别较晚到达；删除后，约 300ms RTT 的十类别测试在第二类收到 WAIT，再次往返超出保守许可窗口，仅发送 1 次。保留接收后等待的集成回归为 29／30，通过该失败定位了预约与实际放行屏障错位。

新迁移 `20261029000000_amap_admission_slot_alignment` 只替换 reserve v1 函数，将预约时刻同时对齐实际放行屏障；原有迁移文件保留。测试核验重复应用迁移后资源状态、用量、绑定及政策版本逐项保持原样。最终 grant v1 的资源锁、版本检查、防重、额度、速率及扣减逻辑沿用；预约后发生的并发变化仍可触发一次 WAIT 复查。

另曾尝试按本地 reserve 调用起点计算预约等待。实际 PostgreSQL 揭示提前到达会直接收到 `ADMISSION_WAIT_EXCEEDED`，因此最终实现保留接收后等待。数据库采样时刻、网络上／下行及客户端时钟之间的关系缺少可用保证，RTT 直接扣除会引入提前到达；这段必要等待与固定类别间隔分别处理。该尝试在最终交付前已撤回。

## Stage B：分类事实与调度策略

| 错误 | 性质／影响范围 | 当前搜索策略 |
| --- | --- | --- |
| `UPSTREAM_TIMEOUT`、网络、普通 HTTP、格式或业务错误 | 单次调用 | 当前类别失败，继续下一类 |
| `ADMISSION_WAIT_EXCEEDED` | 类别超时 | 当前类别记录公开原因；有整体预算时继续，无 termination |
| 日／月准入额度耗尽 | 共享 admission 资源额度 | 停止当前共享链路，保留完成结果，余下类别 skipped |
| 高德明确日额度耗尽 `10003` | 共享高德凭据额度 | 停止当前共享链路，公开为 `DAILY_BUDGET_EXHAUSTED`；首类失败 429，已有结果则部分成功 |
| `ADMISSION_UNAVAILABLE` | 共享准入依赖故障 | 停止后续同一链路；保留安全错误协议及已完成结果 |
| 高德认证、HTTP 401／403 | 共享高德凭据故障 | 停止后续同一凭据链路，安全公开码 `SERVICE_UNAVAILABLE` |
| `REQUEST_DEADLINE_EXCEEDED` | 整个请求预算耗尽 | 有完成结果时返回部分成功、超时类别及 skipped；无完成结果时 504 |
| 主动取消、正文超限 | 整个请求 | 沿用 499／413，清理信号与资源 |
| 未知异常 | 内部错误 | 向上抛出，保留安全 500 |

高德日额度码依据 [官方 Web Service 错误码说明](https://lbs.amap.com/api/webservice/guide/tools/info)，本轮核对 `10003` 对应日访问量超限。短时 QPS 等其他业务错误沿用单次调用策略；原始文本和 infocode 继续仅用于安全内部诊断。

`classifyFailure` 提供性质、范围及共享资源种类；调度器明确当前十类别共享 `nearby` 操作与凭据，据此决定停止。现有 `classifyError` 保留为 CLI 报告使用的 action 适配接口。`ADMISSION_UNAVAILABLE` 沿用现有粗粒度协议，包含连接、函数、提交不确定及入口饱和；当前类别共享该依赖，统一停止该搜索的后续尝试。独立请求中的其他操作继续使用自身绑定和生命周期。

搜索使用 `SearchExecutionOptions` 传入 context、diagnostics 及完成快照回调，移除业务层 delay 参数。Route 只在整体期限结束时同步取得安全快照，外层仍及时终止挂起的操作；主动取消保持 499。UI 复用现有部分成功、termination 消息和 skipped 类别限制。历史存储结构保持原状。
