## 已核实的复用链路

按任务要求阅读了 `src/amap/categories.ts`、`client.ts`、`types.ts`、`transport.ts`、`request-context.ts`、`src/server/amap.ts`、`admission.ts`、`src/admission/service.ts`、`src/search/service.ts` 和 `app/api/search/route.ts`。另外核查数据库池和请求政策装配。现有模块能够安全复用，无需改造生产架构。

生产 Route 使用 `createServerAmapClient()`，其中 `createAmapTransport()` 的 `beforeAttempt` 直接来自 `getServerAdmission(credentialId)`。该 hook 通过 `createAdmission()` 调用 PostgreSQL store，先原子预约，在事务外等待，再进行预算和速率联合 grant，返回单次许可。传输层在 HTTP 前执行 `permit.assertValid()`，无 HTTP 重试。

实验复用同一个 `getServerAdmission()` 和 `getRequestPolicy()`；独立装配 transport 的 `beforeAttempt`，只在 transport 校验许可后进入计数/日志包装器，最后调用原生 fetch。实验不直接调用单类别 `searchNearby()`，因此不改变其为单类别赋值的现有语义。测试用真实 `createAdmission()` 搭配假 store 验证 reserve → grant → send 的顺序；没有连接真实 PostgreSQL，也不能据此声称真实资源绑定已验收。

固定的一次性预算锁在请求前预留全部 9 次。跨进程排他锁和每次 HTTP 前同步日志、每行最多一次、全程最多 9 次三层限制共同工作；没有 alternate ledger/reset/resume/页码/并发/重试参数。准入失败、许可失效或任何请求/解析失败立即停止，不补跑。SIGINT/SIGTERM 使用现有 RequestContext 保存已完成记录。

## 限制与后续条件

- 现有 `CATEGORIES` 不含完整正式父子映射；仅精确且唯一的明确编码归属，其他分布保持未确认。未返回/未归属不能解释为附近没有某类别。
- HTTP 状态来自响应头；高德业务失败使用 `non-success` 安全归一化值，不读取/公开现有 transport 未暴露的任意原始状态文本。超时/网络失败不伪造 HTTP 状态。
- 总耗时含准入等待，响应耗时单独记录。Mock 耗时及密度标签不代表真实接口/实际 POI 密度。
- 没有独立类别对照，不能计算相对独立查询保留率；9 次小样本与首屏触顶只能支持探索性观察，不能证明普遍最优类别上限。
- 固定预算锁保护当前 checkout，跨副本或人工删除锁不受分布式约束；这是禁止的人工绕过，不提供重置或补跑操作。程序失败后也保留全部预算预留。
- 正常中断可保存已完成统计；磁盘故障、SIGKILL 或断电不能保证最后一条与两份报告同时持久化。两格式分别原子替换，之前的检查点与预算锁保留。
- 尚未验证真实 Key/credential 绑定、数据库 schema、现有额度和准入资源是否就绪。Live 前需用户单独授权，并人工核对私有三地点、半径、正确环境及既有 nearby 绑定/政策、目录可写和预算锁状态；不满足则拒绝，不为实验修改配置。详细条件与受保护命令在实验说明中。
